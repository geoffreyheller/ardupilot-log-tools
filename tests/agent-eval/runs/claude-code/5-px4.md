I couldn't check the vibration because `flight.ulg` contains no flight data. The file is 16 bytes in total:

```
55 4C 6F 67 01 12 35 | 01 | 00 00 00 00 00 00 00 00
"ULog" magic          | ver| timestamp = 0
```

That is a valid ULog file header with nothing after it. It has no format definitions, no parameters, and no logged topics, so there's no `sensor_accel`, `vehicle_imu_status`, `sensor_combined` or FFT data to look at. A full flight log is normally megabytes. Getting just the header usually means one of these:

- **The download was cut short.** The transfer over MAVLink or QGroundControl was interrupted right after it started.
- **Logging started and stopped straight away.** For example, the vehicle was armed and disarmed at once, or the SD card failed or filled up.
- **The file was copied incompletely**, or this is a placeholder file.

**Next steps:**

2. Before sending it, check the file is a sensible size (several MB for a flight of a few minutes).
3. If you want the full-rate vibration spectrum and not just the summary metrics, set `SDLOG_PROFILE` to include high-rate/IMU data.
